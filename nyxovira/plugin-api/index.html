Start with the minimum manifest and add a browser script only when the generic detector is insufficient.

Plugin files and real minimum

my-plugin/
|-- plugin.json
`-- browser/
    `-- download_target.js

browser/download_target.js is optional when Nyxovira's generic page detector already recognizes the work and chapters.

{
  "id": "my-plugin",
  "match": { "hosts": ["example.com"] },
  "browser": {
    "home_url": "https://example.com/",
    "download_target_script_file": "browser/download_target.js"
  }
}

Nyxovira needs valid JSON, a non-empty folder name or id, at least one match.hosts value, and browser.home_url. For personal use, name, version, tags, schema_version, parser, GitHub, and a public catalog are not required.

FieldMeaning
idStable identifier; strongly recommended. Otherwise the folder name is used.
match.hostsRequired source domains recognized by the plugin.
browser.home_urlRequired page opened by the app browser.
browser.download_target_script_fileOptional site-specific work and chapter logic.
browser.icon_urlOptional for personal use. Prefer the site's own stable public favicon or logo when available.
tagsNot required for personal use. Optional metadata for filters in an external catalog.

Map the source before writing selectors

  • Check official developer documentation, public APIs, OpenAPI or Swagger files, GraphQL, JSON feeds, and documented endpoints.
  • If an API is not visible or documented, inspect the rendered page, loaded scripts, and browser network requests to identify data used by the site's own interface.
  • Map work routes, chapter routes, order, identifiers, titles, covers, text, images, pagination, infinite scrolling, and dynamic loading.
  • Compare API data with the rendered HTML and choose the most complete and stable source.
  • Record limitations and test with more than one work and chapter.
window.__nyxoviraChapterPlan = {
  title: document.querySelector("h1")?.textContent?.trim() || document.title,
  chapters: [
    { id: "chapter-1", title: "Chapter 1", url: "https://example.com/chapter-1" }
  ]
};

The first download action should return the chapter list quickly. Load full chapter text or image pages only after the user selects chapters whenever the site requires separate chapter requests.

window.__nyxoviraPrepareChapter = async function (chapter) {
  const response = await fetch(chapter.url);
  const html = await response.text();
  const page = new DOMParser().parseFromString(html, "text/html");
  return {
    id: chapter.id,
    title: chapter.title,
    contentType: "novel",
    paragraphs: [...page.querySelectorAll(".chapter-content p")]
      .map(node => node.textContent.trim())
      .filter(Boolean)
  };
};

Text chapters use paragraphs. Image chapters use pages, with images accepted for compatibility.

Test in Nyxovira

  1. Keep plugin.json and the optional browser folder inside one plugin folder.
  2. Open Sites, choose Import plugins, and select that folder.
  3. Open the source and verify work recognition and chapter order.
  4. Confirm that the chapter list appears before full chapter data is downloaded.
  5. Download selected text and image chapters and open the saved result.
  6. Repeat after every mapping change.

If the plugin is only for you, the process ends here. No website, public repository, catalog, or tags are necessary.

Independent external catalog

Use this only when you want other people to connect your catalog manually. You control the hosting, plugin files, descriptions, updates, and security. The catalog stays separate from KapiTomo.

plugin-store/
|-- index.html
|-- catalog.json
`-- plugins/
    `-- my-plugin/
        |-- plugin.json
        `-- browser/
            `-- download_target.js

Catalog discovery

<meta name="nyxovira-plugin-catalog" content="./catalog.json">

Catalog format

{
  "schema_version": 3,
  "name": "My plugins",
  "hub_url": "https://example.com/plugin-store/",
  "plugins": [
    {
      "id": "my-plugin",
      "name": "My Plugin",
      "author": "Your name",
      "version": "1.0.0",
      "site_url": "https://source.example/",
      "icon_url": "https://source.example/favicon.ico",
      "manifest_url": "./plugins/my-plugin/plugin.json",
      "tags": ["portuguese", "manga"],
      "status": "active"
    }
  ]
}

hub_url tells Nyxovira which page to open. store_url and homepage are also accepted. Relative manifest_url values are resolved against the catalog URL. A GitHub-hosted entry may instead use repository_url, repository_ref, and plugin_path.

Install button

<button id="install-my-plugin">Install</button>
<p id="install-status"></p>
<script>
  document.getElementById("install-my-plugin").addEventListener("click", () => {
    const status = document.getElementById("install-status");
    const bridge = window.NyxoviraAndroidBridge || window.ArchiveInkAndroidBridge;
    if (!bridge || typeof bridge.installCommunityPlugin !== "function") {
      status.textContent = "Open this page inside Nyxovira.";
      return;
    }
    const result = JSON.parse(
      bridge.installCommunityPlugin("https://example.com/plugin-store/catalog.json", "my-plugin") || "{}"
    );
    status.textContent = result.message || (result.success ? "Installed." : "Installation failed.");
  });
</script>

An external catalog is not reviewed by KapiTomo. Publish over HTTPS, keep author and source information accurate, inspect every distributed file, and test installation from the page opened inside Nyxovira.

Final checklist

Personal plugin

Valid manifest, correct host and home URL, stable mapping, ordered chapters, completed text/image download, and no unnecessary catalog metadata.

External catalog

HTTPS page and JSON, correct author and source, public manifest and icon URLs, independent identity, tested install button, and an update plan.

Arquivos do plugin e mínimo real

meu-plugin/
|-- plugin.json
`-- browser/
    `-- download_target.js

browser/download_target.js é opcional quando o detector genérico de página do Nyxovira já reconhece corretamente a obra e os capítulos.

{
  "id": "meu-plugin",
  "match": { "hosts": ["example.com"] },
  "browser": {
    "home_url": "https://example.com/",
    "download_target_script_file": "browser/download_target.js"
  }
}

O Nyxovira precisa de JSON válido, nome de pasta ou id não vazio, pelo menos um valor em match.hosts e browser.home_url. Para uso pessoal, name, version, tags, schema_version, parser, GitHub e catálogo público não são obrigatórios.

CampoSignificado
idIdentificador estável; muito recomendado. Sem ele, o nome da pasta é usado.
match.hostsDomínios obrigatórios reconhecidos pelo plugin.
browser.home_urlPágina obrigatória aberta pelo navegador do aplicativo.
browser.download_target_script_fileLógica opcional e específica para obras e capítulos do site.
browser.icon_urlOpcional no uso pessoal. Prefira o favicon ou logo público e estável do próprio site quando existir.
tagsDesnecessárias no uso pessoal. Metadados opcionais para filtros em um catálogo externo.

Mapeie a fonte antes de escrever seletores

  • Procure documentação oficial para desenvolvedores, APIs públicas, arquivos OpenAPI ou Swagger, GraphQL, feeds JSON e endpoints documentados.
  • Se uma API não estiver visível ou documentada, examine a página renderizada, os scripts carregados e as requisições de rede do navegador para identificar os dados usados pela interface do próprio site.
  • Mapeie rotas de obra e capítulo, ordem, identificadores, títulos, capas, textos, imagens, paginação, rolagem infinita e carregamento dinâmico.
  • Compare os dados da API com o HTML renderizado e escolha a fonte mais completa e estável.
  • Registre limitações e teste mais de uma obra e mais de um capítulo.
window.__nyxoviraChapterPlan = {
  title: document.querySelector("h1")?.textContent?.trim() || document.title,
  chapters: [
    { id: "capitulo-1", title: "Capítulo 1", url: "https://example.com/capitulo-1" }
  ]
};

O primeiro toque em baixar deve devolver rapidamente a lista de capítulos. Carregue textos completos ou páginas de imagens somente depois que o usuário selecionar capítulos quando o site exigir requisições separadas.

  const response = await fetch(chapter.url);
  const html = await response.text();

Capítulos de texto usam paragraphs. Capítulos de imagens usam pages, com images aceito por compatibilidade.

Testar no Nyxovira

  1. Mantenha plugin.json e a pasta opcional browser dentro de uma única pasta do plugin.
  2. Abra Sites, escolha Importar plugins e selecione essa pasta.
  3. Abra a fonte e confira o reconhecimento da obra e a ordem dos capítulos.
  4. Confirme que a lista de capítulos aparece antes do download dos dados completos.
  5. Baixe capítulos selecionados de texto e imagens e abra o resultado salvo.
  6. Repita o teste depois de cada mudança no mapeamento.

Se o plugin é somente para você, o processo termina aqui. Não são necessários site, repositório público, catálogo nem tags.

Catálogo externo independente

Use esta opção somente quando quiser que outras pessoas conectem seu catálogo manualmente. Você controla a hospedagem, os arquivos, as descrições, as atualizações e a segurança. O catálogo permanece separado do KapiTomo.

loja-de-plugins/
|-- index.html
|-- catalog.json
`-- plugins/
    `-- meu-plugin/
        |-- plugin.json
        `-- browser/
            `-- download_target.js

Descoberta do catálogo

<meta name="nyxovira-plugin-catalog" content="./catalog.json">

Formato do catálogo

{
  "schema_version": 3,
  "name": "Meus plugins",
  "hub_url": "https://example.com/loja-de-plugins/",
  "plugins": [
    {
      "id": "meu-plugin",
      "name": "Meu Plugin",
      "author": "Seu nome",
      "version": "1.0.0",
      "site_url": "https://fonte.example/",
      "icon_url": "https://fonte.example/favicon.ico",
      "manifest_url": "./plugins/meu-plugin/plugin.json",
      "tags": ["portuguese", "manga"],
      "status": "active"
    }
  ]
}

hub_url informa ao Nyxovira qual página abrir. store_url e homepage também são aceitos. Valores relativos de manifest_url são resolvidos a partir da URL do catálogo. Uma entrada hospedada no GitHub pode usar repository_url, repository_ref e plugin_path.

Botão de instalação

<button id="install-my-plugin">Instalar</button>
<p id="install-status"></p>
<script>
  document.getElementById("install-my-plugin").addEventListener("click", () => {
    const status = document.getElementById("install-status");
    const bridge = window.NyxoviraAndroidBridge || window.ArchiveInkAndroidBridge;
    if (!bridge || typeof bridge.installCommunityPlugin !== "function") {
      status.textContent = "Abra esta página dentro do Nyxovira.";
      return;
    }
    const result = JSON.parse(
      bridge.installCommunityPlugin("https://example.com/loja-de-plugins/catalog.json", "meu-plugin") || "{}"
    );
    status.textContent = result.message || (result.success ? "Instalado." : "Falha na instalação.");
  });
</script>

Um catálogo externo não é analisado pelo KapiTomo. Publique em HTTPS, mantenha autor e fonte corretos, examine todos os arquivos distribuídos e teste a instalação pela página aberta dentro do Nyxovira.

Checklist final

Plugin pessoal

Manifesto válido, host e página inicial corretos, mapeamento estável, capítulos ordenados, download completo de texto/imagens e nenhum metadado de catálogo desnecessário.

Catálogo externo

Página e JSON em HTTPS, autor e fonte corretos, URLs públicas do manifesto e ícone, identidade independente, botão de instalação testado e plano de atualização.
