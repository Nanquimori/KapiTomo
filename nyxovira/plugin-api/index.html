Create plugins for Nyxovira

A plugin connects Nyxovira to a reading site, shows the chapter list quickly, and prepares only the chapters selected by the user.

How a plugin works

The creator publishes a GitHub repository with the plugin files.

The Plugin Hub reads plugin.json to show the name, icon, tags, site, and repository.

Nyxovira installs the plugin and runs browser/download_target.js on supported pages.

The script shows chapters immediately, then prepares the selected text or image pages after the user confirms.

Plugin files

Place the manifest and browser script inside one folder named after the plugin id.

my-plugin/
|-- plugin.json
`-- browser/
    `-- download_target.js
FilePurpose
plugin.jsonDefines the plugin id, version, host, browser entry, icon, and parser.
browser/download_target.jsRuns inside the open page and builds the work download plan.

plugin.json

The manifest describes the site and tells Nyxovira which browser script to run.

{
  "schema_version": 1,
  "id": "my-plugin",
  "name": "My Plugin",
  "version": "1.0.0",
  "match": { "hosts": ["example.com"] },
  "browser": {
    "home_url": "https://example.com/",
    "icon_url": "https://example.com/icon.png",
    "icon_mode": "pinned",
    "short_label": "Source",
    "download_target_script_file": "browser/download_target.js"
  },
  "parser": {
    "adapter": "html_series",
    "base_url": "https://example.com"
  }
}

Site mapping

Map the site's names to the fields Nyxovira expects: title, cover, chapters, text, and page images.

var plugin = {
  siteBaseUrl: "https://example.com",
  siteVariable: "EXAMPLE_WORK_INDEX",
  siteRoutes: {
    detailsHash: "series",
    readerHash: "reader"
  },
  appRoutes: {
    publicSeriesPath: "manga",
    publicChapterPath: "chapter"
  },
  fields: {
    workId: "slug",
    workTitle: "name",
    workSummary: "synopsis",
    workCover: "cover_url",
    workChapters: "episodes",
    chapterParagraphs: "text_blocks",
    chapterPages: "page_urls",
    imageSource: "url"
  }
};

Instant chapter list

When the user taps download, set window.__nyxoviraChapterPlan immediately and return the canonical work URL.

window.__nyxoviraChapterPlan = JSON.stringify({
  title: "Work title",
  summary: "Short summary",
  canonicalUrl: "https://example.com/manga/work/",
  coverUrl: "https://example.com/cover.png",
  chapters: [
    {
      id: "chapter-forest-hunt",
      number: "1",
      title: "The Forest Hunt",
      contentType: "novel",
      paragraphs: ["First paragraph.", "Second paragraph."]
    }
  ]
});

return "https://example.com/manga/work/";

Prepare after selection

For large comics or APIs, keep the first plan lightweight. Load page URLs only after the user confirms selected chapters.

window.__nyxoviraPrepareDownloadPlan = function (context) {
  var selectedIds = Array.isArray(context.selectedChapterIds)
    ? context.selectedChapterIds
    : [];
  var plan = context.chapterPlan;

  plan.chapters.forEach(function (chapter) {
    if (selectedIds.length > 0 && selectedIds.indexOf(chapter.id) < 0) {
      return;
    }

    var payload = getJson(chapter.chapterDataPath);
    chapter.pages = payload.pages.map(function (page) {
      return page.imageUrl;
    });
    delete chapter.chapterDataPath;
  });

  window.__nyxoviraChapterPlan = JSON.stringify(plan);
  return plan;
};

Nyxovira passes { selectedChapterIds, chapterPlan }. The function may return the final plan object or a JSON string. If it returns nothing, the app keeps the original plan.

Chapter formats

Use paragraphs for novels and pages for image chapters. The app also reads images for compatibility.

{
  "id": "chapter-forest-hunt",
  "title": "The Forest Hunt",
  "contentType": "novel",
  "paragraphs": [
    "First paragraph.",
    "Second paragraph."
  ]
}
{
  "id": "chapter-arrival",
  "title": "Arrival at the Ruins",
  "contentType": "images",
  "pages": [
    "https://example.com/page-001.png",
    "https://example.com/page-002.png"
  ]
}

Publishing

The Plugin Hub installs plugins from public GitHub repositories. The repository is the plugin source, and valid catalog entries are published automatically.

The Plugin Hub is a catalog, not a content host. Plugin creators are responsible for their code, site mapping, icons, metadata, permissions, and maintenance. Source sites are responsible for their own pages and content. Nyxovira Pro unlocks app features and does not sell third-party works, pages, chapters, translations, or plugins.

{
  "id": "my-plugin",
  "name": "My Plugin",
  "author": "Author",
  "version": "1.0.0",
  "description": "Site plugin for Nyxovira.",
  "site_url": "https://example.com/",
  "homepage": "https://example.com/",
  "icon_url": "https://example.com/icon.png",
  "repository_url": "https://github.com/user/my-plugin",
  "repository_ref": "main",
  "plugin_path": ".",
  "hosts": ["example.com"],
  "status": "active",
  "tags": ["english", "manga", "novel"]
}

Tags are required. Use one language tag first, then one to three content type tags. Unsupported tags and extra tags are ignored.

Language tags

englishportuguesespanishjapanesekoreanchineseindonesianthaivietnamesefrenchgermanitalianrussianarabic

Content type tags

mangamanhuamanhwanovelwebtooncomic

Review

The Hub checks the repository, icon, official tags, covered hosts, and repository ownership. A visible host can only have one plugin.

Publication

Valid requests are published automatically. Maintainers can remove plugins that violate the catalog rules.

Removal

If the repository or plugin.json disappears later, the entry is removed from the public catalog.

Keep plugin.json and browser/download_target.js in the repository.

Open the Plugin Hub and paste the GitHub repository URL.

Confirm the GitHub request. Automation validates it and publishes valid plugins immediately.

Online

active means the plugin appears as Online.

Offline

broken means the plugin appears as Offline.

Hidden

hidden and removed do not appear in the public catalog.

Automatic checks

The Hub checks plugins every 30 minutes and removes entries whose repository or plugin.json disappears.

Crie plugins para o Nyxovira

Um plugin conecta o Nyxovira a um site de leitura, mostra a lista de capítulos rapidamente e prepara apenas os capítulos escolhidos pelo usuário.

Como um plugin funciona

O criador publica um repositório GitHub com os arquivos do plugin.

O Plugin Hub lê plugin.json para mostrar nome, ícone, tags, site e repositório.

O Nyxovira instala o plugin e executa browser/download_target.js nas páginas compatíveis.

O script mostra os capítulos imediatamente e prepara textos ou páginas de imagem depois da confirmação do usuário.

Arquivos do plugin

Coloque o manifesto e o script do navegador em uma pasta com o mesmo nome do id do plugin.

my-plugin/

`-- browser/
    `-- download_target.js

browser/download_target.jsExecuta dentro da página aberta e monta o plano de download da obra.

Publicação

O Plugin Hub instala plugins a partir de repositórios públicos do GitHub. O repositório é a fonte do plugin, e entradas válidas são publicadas automaticamente.

O Plugin Hub é um catálogo, não um host de conteúdo. Criadores de plugins são responsáveis pelo código, mapeamento do site, ícones, metadados, permissões e manutenção. Os sites de origem são responsáveis por suas próprias páginas e conteúdos. O Nyxovira Pro libera recursos do app e não vende obras, páginas, capítulos, traduções ou plugins de terceiros.

{
  "id": "my-plugin",
  "name": "My Plugin",
  "author": "Author",
  "version": "1.0.0",
  "description": "Site plugin for Nyxovira.",
  "site_url": "https://example.com/",
  "homepage": "https://example.com/",
  "icon_url": "https://example.com/icon.png",
  "repository_url": "https://github.com/user/my-plugin",
  "repository_ref": "main",
  "plugin_path": ".",
  "hosts": ["example.com"],
  "status": "active",
  "tags": ["english", "manga", "novel"]
}

Tags são obrigatórias. Use uma tag de idioma primeiro e depois uma a três tags de tipo de conteúdo. Tags extras ou não suportadas são ignoradas.

Revisão

O Hub verifica repositório, ícone, tags oficiais, hosts cobertos e a propriedade do repositório. Um host visível só pode ter um plugin.

Publicação

Solicitações válidas são publicadas automaticamente. Mantenedores podem remover plugins que violem as regras do catálogo.

Remoção

Se o repositório ou o plugin.json desaparecer depois, a entrada é removida do catálogo público.

Mantenha plugin.json e browser/download_target.js no repositório.

Abra o Plugin Hub e cole a URL do repositório GitHub.

Confirme a solicitação no GitHub. A automação valida tudo e publica imediatamente os plugins válidos.

Online

active significa que o plugin aparece como Online.

Offline

broken significa que o plugin aparece como Offline.

Oculto

hidden e removed não aparecem no catálogo público.

Verificações automáticas

O Hub verifica plugins a cada 30 minutos e remove entradas cujo repositório ou plugin.json desapareceu.
