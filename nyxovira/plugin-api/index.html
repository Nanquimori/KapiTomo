Developer path

1. Create the plugin

Prepare plugin.json, map the site, and build chapter downloads.

2. Test the ZIP in the web laboratory

Use the hosted browser test without installing the Android app or opening an emulator.

3. Validate the complete result

A plugin is ready only after a real chapter is downloaded, saved, and reopened successfully.

4. Distribute later, if needed

Distribution is a separate optional step and does not change how the plugin itself is created.

How a plugin works

The creator starts with plugin.json and browser/download_target.js. The script performs source-specific discovery and builds the chapter plan.

During development, the creator imports the local plugin folder into Nyxovira and tests it on the supported site.

The plugin may remain private. Publication is optional and happens only after testing.

Legacy manifests may omit the script and use the generic page detector, but new plugins need the script to pass the documented conformance workflow.

Choose the implementation level

1. Simple HTML

Use browser/download_target.js to read rendered HTML and produce the complete chapter plan.

2. Simple JSON API

Use the browser script for discovery and declare parser when the native downloader must repeat structured API requests outside the WebView.

3. Dynamic, protected, or encrypted API

parser is mandatory for endpoints, special headers, and decoding; the browser script still handles discovery and the browser session.

Parser optional only means that a manifest can be imported without one. It should be declared for a structured API, special headers, encryption, or native downloading outside the WebView.

plugin.json

Minimum required by Nyxovira

This is the smallest practical manifest for importing and testing a plugin:

{
  "id": "my-plugin",
  "match": { "hosts": ["source.invalid"] },
  "browser": {
    "home_url": "https://source.invalid/",
    "download_target_script_file": "browser/download_target.js"
  }
}

To load the source, Nyxovira only needs valid JSON, a non-empty folder name or id, at least one match.hosts entry, and browser.home_url. The example also names the browser script because it is the reliable way to recognize works and chapters. Without it, Nyxovira tries generic page detection, which may not understand every site.

Not required to import the plugin: schema_version, name, version, tags, browser.icon_mode, browser.short_label, GitHub, a catalog, or a plugin website. Declare parser whenever the source needs a structured API, special headers, encryption, or native downloading. If the site provides a stable public favicon or logo, use its URL in browser.icon_url; otherwise the icon may be omitted.

Site mapping

Map the site's names to the fields Nyxovira expects: title, cover, chapters, text, and page images.

Discover the data source first

  • Look for official developer documentation, a public API, OpenAPI or Swagger files, GraphQL, JSON feeds, and documented endpoints.
  • If the API is not linked or documented, inspect the page source, loaded scripts, and the browser's network requests to identify the endpoints used by the site's own interface.
  • Compare the API data with the rendered HTML and use the most complete and stable source for works, chapters, text, and images.

Mandatory pre-ZIP map

  • Record a real work URL, reader URL, and the work, chapter, and page endpoints.
  • Record selectors, load completion, required headers, referer, cookies, login/tokens, and encryption.
  • Record paid or restricted chapters, source/display order, relative URL bases, and real ID formats.
  • Resolve at least one actual chapter into nonempty pages or paragraphs. Never invent endpoints, selectors, headers, keys, or results.
var plugin = {
  siteBaseUrl: "https://source.invalid",
  siteVariable: "SANITIZED_WORK_INDEX",

    readerHash: "reader"

  appRoutes: {
    publicSeriesPath: "manga",

Prepare after selection

For large comics or APIs, keep the first plan lightweight. Load page URLs only after the user confirms selected chapters.

window.__nyxoviraPrepareDownloadPlan = function (context) {
  var selectedIds = Array.isArray(context.selectedChapterIds)
    ? context.selectedChapterIds
    : [];
  var plan = context.chapterPlan;

  plan.chapters.forEach(function (chapter) {
    if (selectedIds.length > 0 && selectedIds.indexOf(chapter.id) < 0) {
      return;
    }

    var payload = getJson(chapter.chapterDataPath);
    chapter.pages = payload.pages.map(function (page) {
      return page.imageUrl;
    });
    delete chapter.chapterDataPath;
  });

  window.__nyxoviraChapterPlan = JSON.stringify(plan);
  return plan;
};

Nyxovira passes { selectedChapterIds, chapterPlan }. The function may return the final plan object or a JSON string. If it returns nothing, the app keeps the original plan.

ID invariant: every chapterPlan.chapters[].id must exactly equal the corresponding value received in selectedChapterIds. Never add or remove an id: prefix, convert it to a slug, or replace it with the visible index.

Native parser contract

Supported adapters are next_payload, html_series, and aes_json_api. Route fields build work, chapter, reader, bootstrap, page, and CDN requests; request_headers supplies static API headers; map and *_keys map actual JSON paths; route prefixes and image hints control recognition; and encryption fields activate decoding with mapped key material. See the Markdown reference for the operational meaning of every field.

Headers, dynamic APIs, and encrypted APIs

Authentication / headers

Map referer, cookies, login, static headers, and per-page tokens separately. A browser-plan page may use { url, headers }; Nyxovira carries those headers into the native image request. Never assume WebView cookies reach native requests unless the required value is explicitly included, and never embed personal credentials.

Dynamic APIs

Keep discovery light, resolve only selected chapters, and exercise pagination or rotating tokens through the last page. The current in-app prepare hook must finish synchronously.

Encrypted APIs

Declare only legitimately observed formats and key material. A declared format is not proof; content must decode and the complete chapter must be saved.

Troubleshooting

For 401/403 check transport requirements; for missing chapters check selectors, pagination and mapping; for empty pages check URL bases, CDN and decoding. If page one works but a later page fails, the plugin is not valid.

Test in the web laboratory

The limited laboratory is the normal plugin development loop. It does not include the library, settings, catalogs, favorites, or permanent downloads. Nyxovira does not require catalog tags or a separately hosted icon to test a plugin. When the site already provides a public favicon or logo, use it in browser.icon_url.

Keep plugin.json and the browser folder together, then create one ZIP.

Open the Plugin Laboratory, upload the ZIP, and enter the URL of a real work.

The hosted test validates the manifest, mapping, chapter IDs, and the complete content of the first chapter.

Copy the JSON report. The ZIP, navigation, and collected content are released before the response is returned.

Conformance gate

Open the Web Plugin Laboratory

Upload the ZIP and enter the work URL. The hosted service chooses the first chapter automatically and returns PLUGIN_VALID only after downloading every page in that chapter. It never approves a partial chapter. No local service, command line, APK, ADB, or emulator is required.

The result must contain temporaryDataReleased: true and stored: false. Without real network validation, state: not validated against the real site.

Complete sanitized examples: simple HTML, JSON API, novel, manga, and encrypted API. All use the reserved source.invalid domain.

Plugin creation ends after complete validation. Tags, schema_version, GitHub, a public catalog, and a plugin website are distribution metadata, not requirements for creating or importing the plugin. Use the site's favicon or logo when available; you do not need to host a separate icon.

Optional distribution after validation

If you later choose to share the finished plugin, host your own independent external catalog. This is a separate process and does not create another type of plugin.

External plugin store

This optional step comes only after plugins are ready and tested. It explains how to maintain an independent distribution; it is not a second plugin-creation mode.

A minimal external store can use this structure:

plugin-store/
|-- index.html
|-- catalog.json
`-- plugins/
    `-- my-plugin/
        |-- plugin.json
        `-- browser/
            `-- download_target.js

Host the folder at a public HTTPS address. The appearance, search, and plugin cards belong to the store itself; Nyxovira only needs to discover the catalog and receive the installation request. Add one object to the plugins list for every distributed plugin and identify its author and source site correctly.

Catalog discovery

Declare the catalog in the store's main page. A meta tag with the same name and a content URL is also supported.

<link rel="nyxovira-plugin-catalog" href="catalog.json">

Without a declaration, Nyxovira looks for catalog.json, catalog-store.json, and plugins.json in the page's directory. Users may also connect the JSON URL directly.

External catalog

{
  "schema_version": 1,
  "name": "My plugin store",
  "hub_url": "https://plugins.source.invalid/",
  "plugins": [{
    "id": "my-plugin",
    "name": "My Plugin",
    "author": "Author",
    "version": "1.0.0",
    "manifest_url": "plugins/my-plugin/plugin.json",
    "icon_url": "https://source.invalid/icon.png",
      "site_url": "https://source.invalid/",
      "status": "active"
  }]
}

hub_url identifies the storefront when a JSON URL is connected directly. store_url and homepage are accepted aliases. Relative URLs are resolved against the catalog URL. Repository-based entries may use repository_url, repository_ref, and plugin_path.

Direct installation

This complete example creates the button, explains when the page is open outside the app, and displays the result returned by Nyxovira.

<button id="install-my-plugin" type="button">Install My Plugin</button>
<p id="install-status" aria-live="polite"></p>

<script>
  const catalogUrl = new URL("catalog.json", location.href).href;
  const status = document.querySelector("#install-status");

  document.querySelector("#install-my-plugin").addEventListener("click", () => {
    const bridge = globalThis.NyxoviraAndroidBridge
      || globalThis.ArchiveInkAndroidBridge;

    if (!bridge || typeof bridge.installCommunityPlugin !== "function") {
      status.textContent = "Open this site from Nyxovira to install.";
      return;
    }

    try {
      const result = JSON.parse(
        bridge.installCommunityPlugin(
          catalogUrl,
          JSON.stringify({ id: "my-plugin" })
        ) || "{}"
      );
      status.textContent = result.message
        || (result.success ? "Plugin installed." : "Could not install the plugin.");
    } catch (error) {
      status.textContent = "Could not complete the installation.";
    }
  });
</script>

When the store is open in a regular browser, the example tells the person to open it from Nyxovira. Inside the app, the button installs the matching plugin from the connected catalog.

Before launching your external catalog

Host the page, catalog, and plugin files at public HTTPS addresses.

For every plugin, accurately identify the author, source site, and manifest path.

Test the Install button by opening the store from its card under External sites in Nyxovira.

Test before sharing

Publish every file over HTTPS.

In Nyxovira, open Sites → External sites and connect the store page or directory.

Open the connected site from its card and tap Install.

Confirm the message returned by the installation.

Final checklist

Validated plugin

Valid JSON, a non-empty folder name (or id), at least one supported host, a valid home URL, and a browser script tested against real content; use paragraphs for novels or pages for comics. A real chapter must finish, be saved, and reopen successfully.

If you later distribute it, follow the separate external-catalog section after this checklist.

Mapeamento do site

Relacione os nomes usados pelo site com os campos que o Nyxovira espera: título, capa, capítulos, texto e imagens.

Descubra primeiro de onde vêm os dados

  • Procure documentação oficial para desenvolvedores, API pública, arquivos OpenAPI ou Swagger, GraphQL, feeds JSON e endpoints documentados.
  • Se a API não estiver visível ou documentada, examine o código da página, os scripts carregados e as requisições de rede do navegador para identificar os endpoints usados pela própria interface do site.
  • Compare os dados da API com o HTML renderizado e use a fonte mais completa e estável para obras, capítulos, textos e imagens.

Preparar depois da seleção

Para quadrinhos grandes ou APIs, mantenha o primeiro plano leve. Carregue as URLs das páginas somente depois que o usuário confirmar os capítulos escolhidos.

window.__nyxoviraPrepareDownloadPlan = function (context) {
  var selectedIds = Array.isArray(context.selectedChapterIds)
    ? context.selectedChapterIds
    : [];
  var plan = context.chapterPlan;

  plan.chapters.forEach(function (chapter) {
    if (selectedIds.length > 0 && selectedIds.indexOf(chapter.id) < 0) {
      return;
    }

    var payload = getJson(chapter.chapterDataPath);
    chapter.pages = payload.pages.map(function (page) {
      return page.imageUrl;
    });
    delete chapter.chapterDataPath;
  });

  window.__nyxoviraChapterPlan = JSON.stringify(plan);
  return plan;
};

O Nyxovira passa { selectedChapterIds, chapterPlan }. A função pode retornar o plano final como objeto ou JSON. Se não retornar nada, o app mantém o plano original.

Invariante de ID: cada chapterPlan.chapters[].id deve ser exatamente igual ao valor correspondente recebido em selectedChapterIds. Nunca acrescente ou remova o prefixo id:, converta para slug ou troque pelo índice visual.

Os adaptadores aceitos são next_payload, html_series e aes_json_api. O Markdown descreve o efeito operacional de cada campo.

Headers, APIs dinâmicas e APIs criptografadas

Autenticação / headers

Mapeie referer, cookies, login, headers estáticos e tokens por página separadamente. Uma página do plano do navegador pode usar { url, headers }; o Nyxovira transporta esses headers para a requisição nativa da imagem. Não suponha que cookies da WebView chegam às requisições nativas sem incluir explicitamente o valor necessário e nunca inclua credenciais pessoais.

APIs dinâmicas

Mantenha a descoberta leve, resolva somente capítulos selecionados e percorra paginação ou tokens rotativos até a última página. O hook de preparação atual do app deve terminar de forma síncrona.

APIs criptografadas

Declare somente formatos e material de chave observados legitimamente. Declarar o formato não prova nada; o conteúdo deve ser decodificado e o capítulo completo precisa ser salvo.

Solução de problemas

Em 401/403 confira transporte; sem capítulos confira seletores, paginação e mapeamento; sem páginas confira URL base, CDN e decodificação. Se a página 1 funciona e outra falha, o plugin não é válido.

Barreira de conformidade

Abrir o Laboratório Web de Plugins

Envie o ZIP e informe a URL da obra. O serviço hospedado escolhe o primeiro capítulo automaticamente e só retorna PLUGIN_VALID depois de baixar todas as páginas desse capítulo. Ele nunca aprova um capítulo parcial. Não é necessário serviço local, linha de comando, APK, ADB ou emulador.

O resultado precisa conter temporaryDataReleased: true e stored: false. Sem validação real de rede, informe: não validado contra o site real.

Exemplos completos e sanitizados: HTML simples, API JSON, novel, manga e API criptografada. Todos usam o domínio reservado source.invalid.

A criação termina depois da validação completa. Tags, schema_version, GitHub, catálogo público e site de plugins são metadados de distribuição, não requisitos para criar ou importar o plugin. Use o favicon ou logo do próprio site quando existir; você não precisa hospedar um ícone separado.

Distribuição opcional após validar

Se depois você decidir compartilhar o plugin pronto, hospede seu próprio catálogo externo independente. Esse é um processo separado e não cria outro tipo de plugin.

Loja externa de plugins

Esta etapa opcional vem somente depois que os plugins estiverem prontos e testados. Ela explica como manter uma distribuição independente; não é um segundo modo de criação de plugin.

Uma loja externa mínima pode usar esta estrutura:

plugin-store/
|-- index.html
|-- catalog.json
`-- plugins/
    `-- my-plugin/
        |-- plugin.json
        `-- browser/
            `-- download_target.js

Hospede a pasta em um endereço HTTPS público. A aparência, a busca e os cards pertencem à própria loja; o Nyxovira precisa apenas descobrir o catálogo e receber a solicitação de instalação. Adicione um objeto à lista plugins para cada plugin distribuído e informe corretamente seu autor e site de origem.

Descoberta do catálogo

Declare o catálogo na página principal da loja. Também é aceita uma tag meta com o mesmo nome e a URL em content.

<link rel="nyxovira-plugin-catalog" href="catalog.json">

Sem uma declaração, o Nyxovira procura catalog.json, catalog-store.json e plugins.json na mesma pasta da página. O usuário também pode conectar diretamente a URL do JSON.

Catálogo externo

{
  "schema_version": 1,
  "name": "Minha loja de plugins",
  "hub_url": "https://plugins.source.invalid/",
  "plugins": [{
    "id": "my-plugin",
    "name": "My Plugin",
    "author": "Author",
    "version": "1.0.0",
    "manifest_url": "plugins/my-plugin/plugin.json",
    "icon_url": "https://source.invalid/icon.png",
      "site_url": "https://source.invalid/",
      "status": "active"
  }]
}

hub_url identifica a página da loja quando uma URL JSON é conectada diretamente. store_url e homepage são aliases aceitos. URLs relativas são resolvidas a partir do catálogo. Entradas baseadas em repositório podem usar repository_url, repository_ref e plugin_path.

Instalação direta

Este exemplo completo cria o botão, informa quando a página está fora do aplicativo e mostra o resultado retornado pelo Nyxovira.

<button id="install-my-plugin" type="button">Instalar My Plugin</button>
<p id="install-status" aria-live="polite"></p>

<script>
  const catalogUrl = new URL("catalog.json", location.href).href;
  const status = document.querySelector("#install-status");

  document.querySelector("#install-my-plugin").addEventListener("click", () => {
    const bridge = globalThis.NyxoviraAndroidBridge
      || globalThis.ArchiveInkAndroidBridge;

    if (!bridge || typeof bridge.installCommunityPlugin !== "function") {
      status.textContent = "Abra este site pelo Nyxovira para instalar.";
      return;
    }

    try {
      const result = JSON.parse(
        bridge.installCommunityPlugin(
          catalogUrl,
          JSON.stringify({ id: "my-plugin" })
        ) || "{}"
      );
      status.textContent = result.message
        || (result.success ? "Plugin instalado." : "Não foi possível instalar.");
    } catch (error) {
      status.textContent = "Não foi possível concluir a instalação.";
    }
  });
</script>

Quando a loja é aberta em um navegador comum, o exemplo orienta a pessoa a abri-la pelo Nyxovira. Dentro do aplicativo, o botão instala o plugin correspondente no catálogo conectado.

Antes de lançar seu catálogo externo

Hospede a página, o catálogo e os arquivos dos plugins em endereços HTTPS públicos.

Para cada plugin, informe corretamente o autor, o site de origem e o caminho do manifesto.

Teste o botão Instalar abrindo a loja pelo cartão criado em Sites externos no Nyxovira.

Teste antes de divulgar

Publique todos os arquivos em HTTPS.

No Nyxovira, abra Sites → Sites externos e conecte a página ou pasta da loja.

Abra o site conectado pelo cartão e toque em Instalar.

Confirme a mensagem retornada pela instalação.

Checklist final

Plugin validado

JSON válido, nome de pasta (ou id) não vazio, pelo menos um host compatível, URL inicial válida e script do navegador testado com conteúdo real; use paragraphs para novels ou pages para quadrinhos. Um capítulo real precisa terminar, ser salvo e reabrir com sucesso.

Se depois você distribuir o plugin, siga a seção separada de catálogo externo após este checklist.
