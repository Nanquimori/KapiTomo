Publish

Publish a ready plugin

Paste the GitHub repository that already contains plugin.json. The Hub opens a GitHub request and publishes entries that pass the technical checks and accept the catalog rules.

Publishing confirms that the creator controls the repository and accepts responsibility for the plugin code, metadata, permissions, maintenance, and source mapping. Automatic validation is not an endorsement of third-party content.

How publishing works

Prepare the plugin

Keep the manifest and browser script organized in the repository.

Publish on GitHub

The plugin stays in your repository, and KapiTomo publishes only the catalog entry.

Add it to the catalog

Use the publication button and confirm on GitHub. Automation updates the catalog when it finishes.

Remove

Remove a publication

Enter the published plugin and confirm the GitHub request. Plugin owners can remove their own plugins automatically, and maintainers can remove any plugin.

@

Ownership

Who can manage a plugin?

The Hub compares the GitHub account that opens the request with the repository owner saved in the catalog.

  • joao123 can publish and remove joao123/PluginManga.
  • maria456 can publish and remove maria456/PluginNovel.
  • joao123 cannot remove Maria's plugin maria456/PluginNovel.
  • Nanquimori can remove both to moderate the catalog.

The typed link and ID identify the plugin; authorization comes from the GitHub account that creates the issue.
